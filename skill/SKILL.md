# 随记 · suiji-journal

把用户给的素材（对话 / 文件 / 图片 / 链接 / 任何灵感）变成一篇随笔，
加密写入随记 vault，构建加密数据并推送到 GitHub Pages。网页端是密码解锁的
加密时间轴（仓库中没有任何明文），推送后约 1 分钟自动上线。

**每次记录只产出一条随记**（一次一篇，不拆多篇、不顺手多记；除非用户明确要求记两条）。

## 路径与命令

- 项目目录：`/Users/dingze/Documents/工作目录/AI/项目/suiji-journal`
- 查看密码在 `项目目录/journal.config.json`（本机私有文件，**绝不写入 vault、绝不提交、绝不在回答中展示**）。
- 一切命令在项目目录下执行：

```bash
cd "/Users/dingze/Documents/工作目录/AI/项目/suiji-journal"

# 1) 写好随笔 markdown（模板见下）后，连同图片/附件一起导入：
node tools/import.js --date 2026-10-20 --tags 职场,沟通 草稿.md 图1.webp

# 2) 只构建加密数据（不推送）：
node tools/build.js

# 3) 构建并推送到 GitHub（Pages 自动更新）：
node tools/publish.js --message "add: 2026-10-20 随笔 · 顺势而为"

# 直接从一段文本生成并推送（无草稿文件时）：
node tools/import.js --text "随笔全文…" --date 2026-10-20 --tags 职场 --push

# 仅当用户明确要求「沉淀一条/建个专题」时才用（平时不要建）：
node tools/import.js --collection --title "专题名" --date 2026-10-20 草稿.md
```

`import.js` 会自动：把图片/音频/文档复制进 `vault/Attachments/`（统一命名 `<日期>-<原名>`）、
改写正文中的附件引用、补齐 frontmatter、放入正确目录（`01-Journals/YYYY/MM/YYYY-MM-DD.md`
或 `02-Collection/<标题>.md`），然后构建。`--push` 一步到推送。

## 标准流程（5 步）

1. **收集素材**：用户给的全部内容——说的话、转发的聊天记录、图片、录音、文档、链接。
   图片/文件请先读取（图片要读图理解内容；文档读全文），不要只看文件名。
2. **提炼**：找出「触动点」——用户真正在意的瞬间、金句、情绪、结论。保留原话（引文用 `>` 引用块）。
3. **生成随笔**：按下面模板写 markdown。语气：朴素、真诚、第一人称、不喊口号、不堆砌辞藻；
   宁短勿长；不确定的细节不要编造。
4. **导入**：`node tools/import.js`（带 `--date --tags`，附件文件一并传入）。日期默认今天，
   除非素材里明确是别的日子。生成后**告知用户写到了哪篇、推送是否成功**，不要展示密码。
5. **就一条**：本次记录到此为止。只有用户**主动说**「再沉淀一个专题」时才建 02-Collection
   笔记，并在随笔「关联」段用 `[[02-Collection/专题名]]` 关联。

## 模板：日记随笔（01-Journals）

```markdown
---
date: 2026-10-19
title: 顺势而为          # 卡片标题，3-8 字，概括触动点
tags:
  - 观影                 # 第一个标签 = 内容分类（观影/职场/读书/生活/随想…），卡片头部显示它
  - 沙丘                 # 其余是主题标签，2-4 个为宜
  - 人生感悟
---

# 2026-10-19 随笔

> 生命之奥秘并非待解的谜题，而是一个需要经历的现实。
> ——《沙丘》                      # 金句引文置顶；没有值得引的原话就省略引用块

## 触点
- 这件事的来龙去脉：何时、何地、何人、发生了什么。
  （附图 [[Attachments/2026-10-19-沙丘-生命之奥秘.webp]]）

## 思考
- 生活要**顺势而为**，不要逆势而上。   # 第一人称触动与想法，关键词加粗

## 关联
- 原始素材：[[Attachments/2026-10-19-沙丘-生命之奥秘.webp]]
- 相关主题 / 延伸去处（没有就写一两句收束，不硬凑）。
```

## 生成规则

- **触点 / 思考 / 关联** 三段必须齐：触点写事实、思考写想法、关联写去处；哪段实在没有内容就写
  一句「（无）」式的短句，不硬凑、不另造栏目。
- **标签规则**：第一个标签是**内容分类**（观影 / 职场 / 读书 / 生活 / 对话 / 随想…），
  绝不用「文档 / 沉淀 / 素材」这类载体或类型词；其余标签是主题词。
- 引文保留原话，用 `>` 引用块置顶，来源注明（书名/影片/人名）。
- `思考` 写第一人称思考，突出加粗关键词（`**词**`），不写成总结报告。
- 标题取「触动点」，不要「日记」「随笔」这类泛词。
- 附件引用统一 `[[Attachments/文件名]]`（文件名由 import.js 统一，导入时会自动改写）。
- frontmatter 的 date 是唯一日期依据，正文标题行保持 `# YYYY-MM-DD 随笔`。

## 沉淀专题模板（02-Collection，仅在用户主动要求时）

```markdown
---
date: 2026-10-19
title: 处世哲学 · 顺势而为
tags:
  - 处世哲学
  - 原则
  - 顺势而为
---

# 处世哲学 · 顺势而为

**一句话**：生活要顺势而为，不要逆势而上；顺应内心，不要太纠结。

**来源**：2026-10-19 看《沙丘》台词有感 → [[01-Journals/2026/10/2026-10-19]]

**核心**：生命不是待解的谜题，而是需要经历的现实——跟着它的起伏，投身其中，随之流动。

**实践（后续可补充）**：
- 方向不对时，停下来调整，而不是硬扛。
- 做决定前先问自己的内心，不纠结于外界杂音。
```

## 安全红线

1. 查看密码只存在于 `journal.config.json`，**不出现在任何随记、提交、回复、日志里**。
2. `vault/` 是明文工作区，**永远不 git add**（.gitignore 已排除）；只推送 `journal.enc.json` 和 `media/`。
3. 不要修改 `tools/` 加密逻辑（AES-256-GCM + PBKDF2 600000），改了线上会解不开。
4. 网页端 URL 与密码可以告诉用户本人，但不要公开发布到社交平台。

## 验收

- `node tools/build.js` 输出「✓ 已加密 N 篇随记」即成功。
- `git -C 项目目录 log --oneline -1` 有新提交、`git status` 干净（除 vault）。
- 线上 `https://<用户名>.github.io/<仓库名>/` 用密码可解锁、新随记出现在时间轴。
