# 书影模块设计（想读 / 想看清单）

> 设计定稿：2026-10-29 ｜ 实现版本：v1 ｜ 随记产品迭代系列
>
> 定位：网站新增第三个功能页「书影」，与时间轴、日历并列。记录想读/在读/读完的书、
> 想看/在看/看完的影视，每条可承载随时间累积的感想，并与随记双向互链。
> 数据进 vault，与随记同包加密构建，同一查看密码解锁。

## 1. 数据模型

vault 新增 `03-Lists/`，一篇一文件（沿用 01/02 惯例），文件名 `<书|影>-<作品名>.md`，
作品名清洗非法字符（`<>:"/\|?*` 与空白 → `-`），重名自动加 `-2` 后缀。

frontmatter（机器可读，缺失字段按默认处理）：

```yaml
---
added: 2026-10-29      # 入清单日期（唯一日期依据，排序/卡片用）
type: book             # book | movie（预留剧集/纪录片扩展位）
title: 沙丘
creator: 弗兰克·赫伯特 # 作者（书）或导演（影）
year: 1965             # 出版/上映年份，可省
status: want           # want | doing | done（允许回退：doing → want）
priority: 1            # 1=最想（P1 惯例）| 2 | 3，可省
rating:                # 1-5 星，完成后打，可省
started:               # 开始日期，可省
finished:              # 完成日期，可省
progress: 217/500      # 自由文本进度（页数/集数），可省
tags:
  - 科幻
---
```

正文（人读部分，三段自由，**不受随记三段式约束**）：

```markdown
> 为什么想读/想看的一句话（可省）

## 感想
### 10-29 · 读到第三章（日期必填，小标题可省）
感想正文，随时追加……

## 关联
- 相关随记：[[01-Journals/2026/10/2026-10-21]]
- 来源：陈乐推荐（可省）
```

**互链真源唯一**：wiki-link 只写在正文「关联」段（与随记侧对称），frontmatter 不设
link 字段。网页端回链（随记详情显示"相关书影"）由渲染时扫描清单正文的 wiki-link
反向得出，数据量小无性能问题。`[[Attachments/…]]` 照常走附件机制（封面海报可挂图）。

## 2. 状态机

`want → doing → done`，允许回退（在读→想读放回）。`done` 建议带 `finished` 与
`rating`。状态变更发生在 skill/命令行侧（对 AI 说「《沙丘》读完了」），网页只展示——
静态站没有写回能力，与随记交互哲学一致。

## 3. 与随记规则的边界（三条豁免）

清单条目**不是随记**，不受随记三条铁律约束：

1. 条目标题 = 作品名，不按"触动点 3-8 字"取名；
2. 正文是感想时间流（`### 日期 · 小标题` 追加），不写"触点/思考/关联"三段；
3. tags 是纯主题词，没有"首标签 = 内容分类"规则（分类由 type/status 承担）。

**一次一条随记的配额与清单互不占用**：记清单、写感想都不算随记。感想写深了想成篇，
说「把《X》那条感想写成随记」——AI 以该感想为素材扩写标准随记（触点/思考/关联），
导入后在清单那条感想小节尾部追加 `→ 已成随记 [[01-Journals/…]]`，不留悬空。

## 4. 网页端

- 「书影」视图与时间轴并列（侧栏切换），卡片网格：状态徽章 + 标题 + creator·year +
  标签 + 最新感想摘录 + 封面图。
- 顶部一行计数（想读 X · 在读 Y · 读完 Z），筛选条：类型（书/影）、状态、标签、
  关键词搜索（与时间轴共用搜索框）、排序（最近添加 / 优先级 / 评分）。
- 详情复用阅读器：元信息行（状态/进度/评分/creator）+ 感想时间流 + 关联 +
  附件 + **导出原始 md（与随记一致）**。
- **双向互链深链**：`#list-XXX` / `#card-XXX` 互跳并展开；打开详情入 history
  （pushState），浏览器返回键关闭详情回列表（popstate 收口）。随记详情底部显示
  "相关书影"回链（反向扫描得出）。
- 主题走现有 CSS 变量（6 套通吃）、状态徽章只用语义 token 不引新色值、
  移动端 44px 触控 / 安全区 / svh 按 design-science 清单验收。

## 5. 工具链

- `tools/list.js`（新）：`add 书/影 "标题" [--creator --year --why --tags --priority]`、
  `status "标题" want|doing|done [--started --finished --rating]`、`progress "标题" "217/500"`、
  `remark "标题" "感想" [--date --title]`、`link "标题" "01-Journals/…"`、`show`、`list`；
  支持 `--push`。按标题模糊匹配条目，重名/无匹配报候选清单。
- `lib.js`：新增 `scanLists()` 与清单 frontmatter 解析（**不碰加密逻辑**）；
  `scanVault()` 跳过 `03-Lists/`（防清单被当随记收录）。
- `build.js`：清单并入加密包（payload 新增 `lists` 键，**向后兼容**：旧数据无此键、
  旧 app.js 忽略此键）；附件清理同时覆盖随记与清单附件；计数文案涵盖清单。
- 版本号注入（红线 §4.4）：本模块无新增独立 html/js 资源，注入清单不变；
  以后拆出新资源必须同步 build.js 注入。
- 密码管理器、自动锁定、`cache:'no-store'` 附件链路对清单同套生效。

## 6. 兼容矩阵（必须测）

| 场景 | 预期 |
|---|---|
| 旧 app.js × 新数据（含 lists） | 忽略 lists，时间轴正常 |
| 新 app.js × 旧数据（无 lists 键） | 书影 tab 隐藏，时间轴正常 |
| 新数据 lists 为空数组 | tab 可见，显示空清单引导文案 |
| 封面附件同名重加密 + 旧缓存 | `cache:'no-store'` 解密成功 |

## 7. 非目标（v1 不做）

书影音元数据自动抓取（海报简介手动填，可挂图片附件）；上映/出版提醒；
剧集/纪录片独立类型（type 留扩展位）；统计图表（只做一行计数）；
清单条目脱离 vault 另存。

## 8. 实施阶段

1. **数据层**：03-Lists 格式 + lib.js 扫描 + tools/list.js + build.js 并包（先能记）；
2. **网页层**：书影视图 + 筛选 + 详情 + 双向互链深链；
3. **体验件**：感想升格流程、计数、导出一致、skill/README/交接文档同步；
4. 每阶段过本地构建、移动端视口、线上验收。
