# 多设备同步设计（密文载荷自同步）

> 设计定稿：2026-10-30 ｜ 实现版本：v1 ｜ 随记产品迭代系列
>
> 背景：用户以多台不固定设备记录随记。明文 vault 是单机的，加密产物是多机共享的——
> 各设备只看见自己 vault 的明文，直接全量构建会把别人记的记录挤出密文包（10-30 实证：
> 一台设备的推送险些覆盖另一台记的《热气腾腾的幸福》，靠手工解密密文载荷救回）。

## 1. 核心思路：密文载荷自同步

**不新增任何基础设施。** `journal.enc.json` 里每篇随记/清单条目都带 `raw`（完整明文原文），
附件是内容哈希命名的独立密文（同 salt 解密）——**密文载荷本身就是一套完整的明文运输载体**。
让每台设备在记录推送前先从远端载荷把缺的明文"补"回自己的 vault，再全量构建推送；
谁后推送，谁的构建天然包含所有人的记录。

- 明文**永不出本机**（不建明文私有仓，守住"仓库里没有任何明文"的产品承诺）
- git 当运输层（公开仓只有密文，clone 无需凭证）
- 站点查看密码兼任同步密码（每设备手动配置一次，同现状）

## 2. 同步闭环（每次记录自动发生）

推送前固定顺序：**fetch → merge → 对账（sync.js）→ build → commit → push**，
push 被拒则整环自动重试（最多 3 轮），仍失败才报错。

**对账铁律：只增不删。** 远端载荷里有而本地 vault 没有的随记/清单条目/附件，
解密写回本地 vault；两边都有的对比原文，一致跳过。远端没有 ≠ 被删除
（v1 无删除功能；将来做删除需配 tombstone，此处预留）。

**撞车处理**（两设备几乎同时推送）：merge 时冲突只应发生在**可再生构建产物**
（journal.enc.json / media/* / index.html / app.js 的时间戳行）上——这类冲突直接取
远端版本后继续（build 会全量重造所有产物）；若冲突含非产物文件（如文档/工具），
停下报错交给人。合并后对账把对方的明文长回来，重建全量推送。

**同条目双改**（罕见：A 加感想、B 改状态）：**本地版本为准**，远端版本整篇存入
`vault/_sync-conflicts/<原 rel>-<时间戳>`（不参与构建）并大声警告，零丢失、人工合并。
v1 不做字段级智能合并，宁可留痕。

## 3. 新设备冷启动 = 灾难恢复

一台全新设备只需三步：
1. `git clone <公开仓>`（无需凭证）
2. 复制 `journal.config.example.json` 为 `journal.config.json`，填同一个查看密码
3. `node tools/sync.js`——vault 从零长出全部历史随记、书影清单与附件

vault 整个丢失同样用这招从密文载荷长回来（2026-10-30 已实证可行）；
git 历史里每一版载荷都是恢复点。

## 4. 工具链

- `tools/sync.js`（新）：从 `origin/main` 的密文载荷对账补明文，输出恢复/跳过/冲突报告；
  `--pull` 为冷启动语义别名（行为相同）。解密用与站点同参数（PBKDF2 600k / AES-256-GCM），
  **不改任何加密逻辑**。
- `tools/publish.js`：重写为 §2 闭环（自动 merge + 对账 + 重试）。
- `tools/lib.js`：补 `decryptPayload` / `decryptAttachment`；vault 扫描豁免 `_sync-conflicts/`。
- skill/README：**记录一律走 `--push`**（让闭环生效），不要手动 build + 手动 push；
  推送被拒（fetch first）时**禁止盲推或直接覆盖**，`publish.js` 会自动处理。

## 5. 测试矩阵（/tmp 裸仓模拟双设备，真实 git + 真实加解密）

| 场景 | 预期 |
|---|---|
| B 全新 clone + sync（冷启动） | 长出 A 的全部随记/清单/附件 |
| B 记一条 push → A sync | A vault 长出 B 的记录，两边齐全 |
| 双设备各自构建同时推（撞车） | push 被拒 → 自动 merge+对账+重建 → 双方记录都在远端 |
| 同条目双改 | 本地版本保留，远端版本入 `_sync-conflicts/`，零丢失 |
| 对账幂等 | 连跑两次 sync，第二次全部跳过 |

## 6. 非目标（v1 不做）

字段级智能合并；删除同步（tombstone）；密码托管/自动分发；无 node 设备（纯手机浏览器）
直记；多站点多密码；实时同步（推送触发即可，不需要守护进程）。

## 7. 一句话

**明文永不出本机，密文载荷兼任同步信使，git 当运输层；只增不删，冲突留痕。**
设备越多越稳——每次推送都是一次全量汇聚。
